# Studio Operations class intelligence

Studio Operations is one continuous workspace. Eight governed metric cards lead into an interactive weekly demand heatmap or recurring-class performance scatter chart, followed by class intelligence, top/bottom performance, schedule changes, booking behaviour, member attendance and the restored Go one level deeper registers. Chart controls include measure, minimum sessions, data view, zoom reset, CSV export and click-to-inspect. Legacy links for tabs 2, 7 and 9 resolve to tab 1. The four studio sub-tabs and duplicate generic registers, rankings and charts have been removed.

## Breakdowns and controls

- Unique class = exact class name and studio. Recurring slot = exact class name, studio, weekday and time. Individual sessions retain session ID and source-row identity.
- The selector contains all 31 grouping modes from the reference repository, including Class + Type, Session Name, Date, AM/PM, morning/evening, weekday/weekend and every instructor combination. The additional analysis catalogue retains 36 curated combinations plus a custom builder for up to five ordered dimensions. Matched-slot instructor face-offs and format specialisation remain available as grouping choices.
- Global date, studio, instructor, class, weekday, time, session-type and capacity filters apply when the source carries the corresponding field. Capacity bands no longer empty booking records that have no capacity field; member-type filters likewise require source member-type data. Local search, hosted-session exclusion, minimum sample, minimum fill and minimum average attendance refine the tables.
- The seven reference column presets retain their original names, order and columns: All Metrics, Performance Focus, Revenue Analysis, Attendance Overview, Capacity Planning, Cancellation Analysis and Consistency Tracking. Headers sort and resize; column controls hide and reorder metrics. Keyboard arrows resize focused separators.
- Ranking cards offer Inspect, Compare, Focus table and View in table actions, list-size controls, top/bottom-only table filters and ranking exports. Selection reveals a side-by-side comparison. Groups expand individual source-session rows immediately underneath, aligned to the same columns, with instructor, class/type, date/day/time, studio and metrics. Child rows open the source-session drill-down. Grouped tables use virtual scrolling; flat tables additionally paginate.
- Save/restore retains the breakdown, metric columns, ranking criterion, thresholds, search, hosted exclusion, sorting, density and column widths and custom grouping in this browser. Global scope continues to come from the existing app filters.
- CSV export includes all filtered table rows, or selected rows. Prior-period values follow the app's comparison selector. Ranking excludes unavailable metrics and samples below the threshold, respects metric direction and never duplicates an entity across top and bottom.

## Metric and schedule interpretation

Session metrics use the existing metric registry and formatters. Fill and per-session measures are recomputed from their numerators and denominators. Earned session revenue is distinct from cash collected. Waitlist fields are read when provided by the source; missing values remain unavailable. Reference composite scoring weights average attendance (40%), fill (35%) and session count (25%), capped at 20 attendees, 100% fill and 50 sessions. Rev Lost follows the reference cancellation-value estimate; it is not measured lost revenue.

Face-offs retain the same studio, exact class, weekday and time with at least two named instructors meeting the sample threshold. These are observed assignments, not controlled experiments. Specialisation compares each instructor with the same format and studio using the selected ranking criterion. The benchmark includes the instructor and respects global filters.

Schedule analysis includes the calendar month preceding the selected start date, so a single selected month has a baseline. It displays changes ending within the selected dates and compares observed recurring slots across adjacent calendar months. It captures instructor-roster and average-capacity changes, unique possible day/time moves, newly observed slots and slots no longer observed. It shows session counts, average attendance, fill and revenue per session before and after. Thresholds must be met on at least one side. Search and hosted exclusion also apply.

Moves require a unique one-dimension match in both directions. Ambiguous or simultaneous day/time moves are left as separate observations. Missing calendar months are not treated as evidence of change. No schedule audit log or future active timetable is available: discontinuations, effective change dates and causal effects cannot be confirmed. Partial months, filtered instructor populations and source coverage can affect detection.

## Source registers and styling

Booking behaviour initially groups by class, weekday, time and instructor. Member attendance initially groups by community member, class and instructor. Each retains expandable source-grain details, independent totals, comparison values, metric selection and drill-downs. Go one level deeper provides room-size utilisation, payment mix, hosted experiences and overbooking pressure, queried when opened; source predicates remain active in selection totals and drill-downs.

The interface uses the current app's fonts, surfaces, colours and compact rows. Group labels truncate, child sessions align with the parent columns, and totals retain pooled metric definitions. Grouping, preset, search, ranking and advanced controls align in a responsive grid. Top/bottom lists use restrained semantic accents and consistent action rows. Every wide table scrolls within its own register rather than expanding the tab. Schedule-change detail cells wrap fully with automatic row height, with dedicated room for class/studio, before/after assignments and evidence; they do not truncate with ellipses. All reference grouping dimensions remain available. Cache schema version 16 refreshes normalized sources, including hosted-session classification from actual booking and check-in class headers.
