# Implementation decisions

1. The pasted brief's explicit “Build it” and running-application deliverables govern the work. The trailing request for a design plan is realised as the application's design system and this documentation. The existing workspace was empty.
2. The actual inventory contains seven unique workbook IDs, not six. All ten named tabs remain configured.
3. No service-account credentials were supplied in this workspace. The supplied workbooks were publicly readable. A server-side public GViz reader provides real data now; the preferred metadata/title-verified Sheets API v4 implementation is ready for credentials. Public mode verifies expected header fingerprints in addition to requesting the sheet by title. Known header drift is explicitly whitelisted and reported.
4. Real headers differ from the brief: Sales combines `Paid In Money Credits`; Lapsed has `Total Sessions Completed`; Checkins has separate `Month` and `Year`. The combined Lapsed field maps to completed sessions only. No separate total-session figure is invented. Checkins month derives from the actual visit date. Unused money/credit fields are not guessed.
5. The initial scope is the most recent completed calendar month in Asia/Kolkata. This avoids treating future sessions with zero attendance as finished empty sessions. An operator can choose current dates, last quarter or all history.
6. Slots and Trainers recompute date-specific metrics from Sessions. Recurring and Teacher Recurring are lifetime rollups with representative dates; applying quarter dates directly to those rollups would produce misleading results. Top-five instructor dependence uses Recurring and is explicitly labelled lifetime evidence.
7. Instructor draw premium compares a trainer's fill with a capacity-weighted average of the same format/location/day/time slots inside the same scope. It does not imply causation.
8. The Overview active base is a current lifecycle snapshot, not the active status of only that month's acquisition cohort. No prior-period lifecycle snapshot exists, so no historical delta is invented.
9. Source values remain intact. Real September Sales data contains net-of-VAT amounts larger than gross payments. These values remain visible with a warning; Data health lists affected source rows. The application does not silently “correct” the workbook.
10. All damaged Excel duration values remain null. There is no 55-minute substitution. Recorded-hour figures cannot be considered complete when the source is damaged.
11. Cost rate defaults to INR 1,200 per taught session. This is an editable estimate, never payroll actually paid. Pipeline, capacity opportunity and membership expiry exposure are estimates with their basis stated. Advertising spend is absent, so CAC and advertising ROAS are unavailable.
12. A 15-minute disk cache and schema-versioned IndexedDB Parquet cache minimise repeat downloads. Sources load for the active workspace; snapshots remain usable past TTL only with explicit freshness/error labels while live refresh runs. Normalisation and insertion occur in 5,000-row batches. Original source JSON is retrieved on demand rather than duplicated throughout the browser database.
13. Hierarchies are SQL rollups with recomputed rates. Selection totals use an OR of selected paths to avoid double-counting descendants when a parent and child are both selected. Above 120 visible rows the table virtualises.
14. A 50,000-group result guard keeps unbounded member-level history from exhausting the renderer. The operator sees a warning and can narrow period/location. Top-level groups are returned first, and their totals remain complete. Original-row drills show up to 500 records and tab source exports show the latest 250, explicitly labelled.
15. Monthly tables use 14 months to include the previous year's comparison month. Missing cells remain unavailable rather than zero-filled. Categories absent from a month in a stacked sales chart represent no transactions, and can legitimately contribute zero to that stack.
16. Both themes use the supplied material and domain palette. Small tertiary text is raised in contrast from the proposed tokens to improve readability. Matte surfaces have no gradients or drop shadows; Gloss uses lacquer top edges and a shadow ladder. Only the active navigation barre can glow.
17. PDF export uses the browser's print/save-PDF facility. Print includes the active filter context, rate assumption and applicable written signals. Module CSV follows visible expansion; tab CSV contains all returned hierarchy levels.
18. Four named saved-view presets select their operational workspace while preserving the operator's chosen dates. User-defined saved views include filter state, workspace, density, comparison and grouping/columns. They remain local to this browser.
19. The companion 478-metric dictionary was not attached. The implemented dictionary is generated from the actual registry; no claim is made that the unavailable catalogue was implemented.
20. The implementation is a local operating application. No upstream sheet was changed, no message was sent and no production deployment was performed.

## Validation boundaries

Build and unit-test success does not establish visual acceptance or performance compliance. Screenshot and interaction evidence is generated separately. The exact performance budgets are assessed in PERFORMANCE.md. Several specialised visual treatments in the original brief—such as lasso selection, row-overlay monthly sparklines, a draggable frozen-column layout, rank trajectory charts and a complete historical retention triangle—are not substitutes for the source-backed core registers and are not represented as verified features.

## Startup and retention upgrades

21. One engine connection serialises reads and atomic table replacements. Unavailable tables are initialised with schema only and never presented as populated sources. Rules skip unavailable dependencies; Data health withholds cross-source comparisons when a source fails.
22. Last-successful snapshots are deliberately visible during refresh, with their original fetch time. Original drill records retrieve immutable versioned raw snapshots. A first-time load without any saved data still depends on Google Sheets availability and throughput.
23. Operational worklists use the current IST date and location, rather than historical purchase filters. Other dashboard filters are explicitly outside this list's eligibility scope. One representative membership is selected per Member ID, prioritising current paid ongoing access then the latest purchase. Concurrent memberships require source review.
24. Renewal candidates have paid ongoing access: multi-session entitlement or a membership/unlimited/package name; complimentary, free and introductory products are excluded. Unknown amounts do not establish a paid renewal opportunity. Attendance cadence uses actual attended dates, and newcomer return rules allow seven days to return. These are explainable outreach rules, not predicted churn probabilities or causal revenue claims.
25. Local server follow-ups persist in the gitignored `.floor/` directory, separately from analytical caches and upstream workbooks, by Member ID. They capture member voice and staff observations separately, keep revision history, and require an outcome to close. Contact availability never establishes consent. No outbound messaging was added.
26. Average class size uses decimal units; intro attendances per session is a count rate, not a percentage. Effective booking attendance counts attended records without adverse flags, avoiding duplicate subtraction. Complimentary share counts attended complimentary records over attended records. Membership utilisation uses bounded Sessions Limit minus Remaining Sessions; the combined lifetime completed field does not establish per-membership usage.

27. Closing a member follow-up records the currently eligible episodes: access product/start/end for renewal and unused access, last attended date for an absence episode, and first-visit date for a newcomer episode. Snapshot refresh timestamps never reopen a closed episode. A new episode returns to the appropriate worklist with owner/contact preference and historical notes preserved. Older records without episode keys reopen only when a later start or attendance date establishes new activity after closure.

28. Atlas preserves legacy browser storage names during the rename so existing views and settings survive. New page customization uses atlas-preferences and syncs with the workspace settings document. Provider credentials use a separate encrypted server store; no browser storage or public repository receives an API key.
29. Month-on-month tables use 14 completed months and inherit non-date global filters. Charts, register data, late cancellations and retention worklists use the selected global dates; memberships use expiry dates. Cohort renewal counts use COUNT FILTER to avoid DuckDB WASM 128-bit integer sums rendering as arrays.
30. Charts share data/CSV, zoom/reset and fullscreen controls. Metric definitions use a viewport-contained portal, and assistant settings are available from both the full workspace and the floating panel. Native agent ingest writes normalized and raw records as batched NDJSON, preserving original source row offsets.
